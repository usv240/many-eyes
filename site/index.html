Twitch chat checks the AI's disaster map.

After a disaster, AI marks thousands of buildings as damaged within days, and nobody can trust those marks until people check them. Many Eyes puts each building on stream, before and after, and lets chat decide whether it survived. Hidden expert checks keep the crowd honest. Anything unclear goes to experts.

AI is fast. Trust is slow.

On 26 August 2026 a glacier collapse sent a flood down the Bhote Koshi valley in Nepal. Within 48 hours the Humanitarian OpenStreetMap Team's AI model had scored over 1,000 buildings for damage, and 8,421 by 12 September. Its output was published as not yet human validated.

Checking is the bottleneck. Trained volunteers on MapSwipe agree with experts 91 to 96% of the time on simple tasks, but damage is harder, and there are never enough of them in the first week.

Twitch has millions of people who already watch together, type together and vote together. Many Eyes points some of that attention at the bottleneck, with rules that keep a crowd honest and a way to say "we are not sure".

How it works on stream

The whole stream is one browser page in OBS. Tap each i on the screenshot to see what that part does.

  1. A tile opens for 15 seconds. The stream shows one building from the Nepal flood, before and after.
  2. Two AI debaters make their case. One argues destroyed, one argues intact, and each points at the photo.
  3. Chat votes 1, 2 or 3. Votes arrive through Twitch EventSub in real time.
  4. The engine validates or refuses. At least 66% weighted agreement from at least 3 voters, or the tile goes to expert review.
  5. The bot posts the result in chat, and an append-only ledger records every vote so anyone can recompute every number.

Run it on your channel

Many Eyes is an OBS browser source and a chat bot. It needs no Twitch extension review, no affiliate status, and no audience to try it.

  • Three modes. demo uses a simulated crowd and needs no keys. demo:mixed adds your real chat to it. live uses real chat only.
  • Chat commands. 1, 2, 3 to vote, and !why for a two-sentence explanation. First-time voters get one short welcome.
  • Careful words. The stream says destroyed, intact, unsure, validated and refused. Nothing scores or celebrates destruction.
  • Light on data. The ledger keeps Twitch user ids and votes for the mission, nothing else.
git clone https://github.com/usv240/many-eyes
cd many-eyes
npm ci
cp .env.example .env
npm run demo          # simulated crowd, no keys
npm run demo:mixed    # plus your real Twitch chat
npm run live          # real chat only

In OBS, add a Browser Source at http://localhost:5180, 1920 by 1080. Live modes need a Twitch user token; the README has the one command that creates it.

How it was built

OpenAI Codex

Built the core in one thread, guided by AGENTS.md rules and two repository skills. Each phase was run, screenshotted and reviewed, then Codex fixed each finding with a test.

OpenAI API

Writes both sides of every debate from the photos alone. Its own label is measured, and never used to decide.

Twitch EventSub

Reads every chat message in real time over a WebSocket, follows reconnects, and ignores duplicates.

Twitch Chat API

Posts one result per tile, answers !why, and welcomes first-time voters, within Twitch's rate limits.

Twitch stream markers

Every decided building drops a marker on the broadcast, so the saved video becomes a searchable index of decisions.

Twitch CLI and OBS

The CLI creates the bot's token in one command. OBS shows the overlay as a browser source, so no extension review is needed.

Claude Code

Planned and reviewed each phase, and built the later parts: mixed live mode, the API, and this site.

Open data

Satellite photos from OpenAerialMap, expert damage grading from Copernicus EMS, and buildings from OpenStreetMap.

Engineering

TypeScript, Fastify, Vite and a hash-chained ledger, with over 170 automated tests.

What this does not prove yet

  • The crowd numbers are simulated. Real streams will measure real viewers, and the hidden checks will report it live.
  • Standing buildings in the hidden checks are inferred: OpenStreetMap buildings more than 40 metres from any Copernicus damage point.
  • Tiles that mislead everyone stay wrong. Consensus cannot catch a shared mistake, so those still need experts.
  • The AI score is one model on one day. It will change as models change, which is why the repository can measure it again.

Questions, in plain words

Is this a game?

It plays like one: a timer, a vote and a reveal. The results are real map data about real buildings, so the words stay careful and nothing rewards destruction.

What is a hidden check?

A building whose answer experts already know. Viewers cannot tell which tiles are checks. Checks measure the crowd's accuracy live and adjust how much each person's vote counts later.

Why not just trust the AI?

On the same photos, the AI called more than half of the standing buildings destroyed. People catch those false alarms, and the hidden checks show whether they did.

What happens to a refused building?

It goes into an expert review queue, exported as its own file. Refusing is safer than guessing on a humanitarian map.

Can trolls ruin it?

A raid can split a tile, which then gets refused. Trolls who keep missing hidden checks lose weight, down to 0.2 of a normal vote. The benchmark tests raids and always-wrong trolls.

Do I need Twitch to try it?

No. The section above, the data page and npm run demo all work without Twitch. Live voting needs a Twitch channel and one token.
